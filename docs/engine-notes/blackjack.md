# Engine notes: Blackjack (21)

This is the REFERENCE implementation other engineers will imitate — make it exemplary and well commented. Seats: 0 = learner, 1 = dealer (forced moves: e.g. {type:'reveal'} to flip the hole card, {type:'dealer-hit'}, {type:'dealer-stand'} — exactly one legal move each time so the UI can animate the dealer one card at a time; the dealer acts only after all learner hands are finished and only if some learner hand is not busted — otherwise just reveal and finish). Learner moves: hit, stand, double, split (double/split only when allowed AND affordable: each needs 1 extra unit, tracked against config.affordableUnits). Peek rule: with an Ace/ten-value upcard the dealer checks for Blackjack right after the deal; if the dealer has it the round ends immediately (learner Blackjack pushes). Learner natural vs no dealer natural ends immediately with +1.5. Also export helpers: handValue(cards) → { total, soft } and basic-strategy logic in strategy.ts (6-deck, S17, DAS, split once) used by coach() and the normal bot (for seat 0 in simulations); 'easy' bot = hit below 15, otherwise stand. coach 'why' examples: 'Dealer shows a 6 — a weak card. Dealers bust a lot from 6, so stand on 12+ and let them bust.' Result flags: tags 'blackjack' for a natural; perfect = natural; bust when every learner hand busted; comeback = won a hand that was at a hard 12–16 and hit; luckyLastCard = reached exactly 21 by hitting, or the dealer busted on their last card while the learner stood on ≤ 16; closeFinish = won/lost by exactly 1 point; bigPot = |net| ≥ 2. Simulation also checks a statistical sanity bound: with the normal (basic strategy) bot over ≥ 20,000 rounds the average net per round is between −0.03 and +0.01 (house edge ≈ 0.5–1% for these rules; widen slightly if needed but justify).
